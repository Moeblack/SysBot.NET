# 宝可梦本地派送台 · 同会话批次版

## 开始使用

1. 解压 Windows x64 包，双击 **start-web.cmd**，浏览器打开 <http://127.0.0.1:5217>。自带运行时，不需安装 .NET、Node.js 或 Discord。
2. 「派一只」使用单只配置；「贴队伍」粘贴 1–12 只传统 Showdown 配置，每只空行分隔，点「一起派送」。全部生成检查通过后才整批入队。
3. 接收机使用离线本地连接交换，密码 **03180318**。**同一批只搜索一次**；每收完一只留在交易盒子，选择下一只普通材料，等对方显示正确目标再确认。本批全部完成后才退出。
4. 多次提交是多个批次，不会跨批次自动合并到同一伙伴。新批次需要重新配对。

**首次先试两只普通宝可梦。** 本版同会话续传需要实机验收，不用老版逐只重新配对的成功记录替代。

## 首次硬件准备

- 派送端：Atmosphère/CFW Switch + usb-botbase；电脑安装对应USB驱动。接收端可为原厂机。
- 目标游戏：两台朱／紫4.0.0，解锁交换；先手动确认本地无线交换可用。
- USB只是电脑控制派送机的通道；两台NS使用原生本地无线，不通过USB互换，也不需要路由器IP LAN。
- 备份派送端存档，**盒子1第1格留作专用工作格，不放收藏**。进入游戏大地图，关闭对话和盒子，两台游戏离线且本地无线可用。
- usb-botbase使用USB模式，设备ID应为057E:3000。包内libusb动态库不是驱动安装器；具体准备见 `SV-LOCAL-TRADE.zh-CN.md`。
- 不要同时用另一个程序或另一实例控制同一台派送机，不要打开DBI MTP抢占USB。

## 批次与盒子

整批在电脑内预生成并校验；一次队列任务包含所有成员。第一只配对，后续复用同一会话及B1S1工作格，**不是同时写入多个盒子格子**。官方任意槽位寻址没有足够证据，本版不猜地址、不覆盖其他格。

B1S1中的接收材料会在下一只载入时被替换。每只实际收到的材料先存为电脑数据目录 `received/<订单ID>.pk9`；存档失败会停止后续覆盖。不会自动将材料搬到别的游戏盒子格，勿把收藏当材料。

批次强制拒绝双方会交换进化的组合，避免动画/学习招式菜单影响续传。对方换材料后需要读到新的个体数据；使用完全相同的克隆材料可能被保守判为旧报价而超时。

## 队列状态与取消

- 每只显示第i/N只与真实状态：待派送、同批等待、准备中、正在搜索交换、交换中、已完成、派送失败、本批已中断/未派送、已取消。
- 开始前可**取消整个批次**；只显示一个整批取消按钮。已经出队/开始的批次不能拆开取消，可在游戏里退出交换停止余下部分。
- 单只完成不等于整批完成；后续中断时保留已完成项，未开始成员标为未派送，不自动重放。
- USB错误立即停机，阻止后续读写/按键以及下一笔任务。新下单不会暗中恢复运行，须先核对收货，再从USB设置显式重连。
- 同一次程序运行中，未编辑时重试复用requestId防重复；浏览器保存输入，程序保存USB端口。
- **关闭程序会清空内存队列和去重记录**。刷新网页不清队列，关闭网页不停止服务。重启或故障后先核对接收盒子，只重提未收到的部分。

## 合法性与配置

复用PKHeX Showdown解析、Auto-Legality生成、PKHeX复检及SysBot可交换性检查；生成后核对请求一致性，不偷偷改球、招式、闪光等来冒充成功。

只生成朱紫原生来源，保持HOME tracker检查，不开放训练家覆盖或批处理修改。单次最多12只；EV单项0–252、合计不超过510，IV单项0–31，等级1–100。冠军SP不自动换算；写成EVs:32就按32EV处理。

有效性格包含薄荷、有效IV包含极限训练，不保证出生性格/IV等价。工具检查通过或本地交换成功，不等于官方对HOME、联网或赛事使用的认可。

## 故障处理

- **USB通信中断**：保持数据线与游戏唤醒，检查驱动/usb-botbase及是否有其他程序占用。核对收货后显式重连；别连续点下单。
- **本批中断**：已完成的不要重发。未派送可单独再提交；当前失败项可能结果不确定，先看接收盒子。
- **准备下一只**：接收方先选择下一只材料，等目标出现再确认；不退出、不重新搜索。
- **无硬件模式**：若设备提示此模式，检查是否设置了 `SYSBOT_WEB_NO_HARDWARE=1`。它用于开发验收，仅生成/排队，禁止扫描和连接Switch。
- **生成超时**：停止接受后续生成，提示重启；ALM超时不能保证底层CPU工作立即取消，不叠加未知任务。
- **连接中断/网页打不开**：检查本地程序仍在运行；默认只监听127.0.0.1，不是手机远程服务。

上游是否支持、FusionBot复用依据、单槽而非多槽的原因、安全边界及实机待验收项：**SV-SESSION-BATCH.zh-CN.md**。交互报告：**flow-report.html**。

```powershell
dotnet build SysBot.NET.slnx -c Release
dotnet test SysBot.NET.slnx -c Release --no-build
npm ci
npx playwright install chromium
npm run test:web
./scripts/publish-web.ps1
```

源码构建需.NET10 SDK；Node/Playwright只供开发测试，用户运行包不需要。`TEST_BROWSER_CHANNEL=msedge`或`chrome`可用已安装浏览器；`TEST_WEB_EXE`可验收独立exe。浏览器测试自动使用独立数据目录与无硬件模式，不连接真实NS。

环境变量：`SYSBOT_WEB_PORT`更换端口；`SYSBOT_WEB_DATA`设置数据/收货档案目录；`SYSBOT_WEB_NO_HARDWARE=1`禁止硬件访问。`--no-browser`禁止自动打开网页。
