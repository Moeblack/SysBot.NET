# 宝可梦本地派送台 · Windows 网页版

## 直接用

1. 解压 `SysBot-SV-Local-Web-win-x64.zip`，双击 **`start-web.cmd`**。它会打开 <http://127.0.0.1:5217>；保留程序窗口，不用安装 .NET、Node.js 或 Discord。
2. **派一只**：默认已填巨金怪，选择种类／闪光后点「派送这一只」。**贴队伍**：粘贴传统 Showdown 配置，点「一起派送」，整批按粘贴顺序排队，不用逐只下单。
3. 接收 Switch 的朱／紫进入**离线本地连接交换**，输入 **`03180318`**。每收完一只，仍用同一码再次搜索，并在游戏里选择交换材料和确认。

网页操作最短是一键排队；这不等于接收端游戏也能免确认。派送端须预先配置好 USB、usb-botbase 与游戏。**不要同时运行桌面版或另一个程序控制同一台派送机。**

## 派送端准备（首次）

- Windows x64；CFW 派送 Switch；[usb-botbase](https://github.com/Koi-3088/usb-botbase) 和对应的 [USB 驱动](https://github.com/kwsch/SysBot.NET/wiki/Configuring-a-new-USB-Connection)。包内 `libusb-1.0.dll` 是用户态运行库，不代替驱动安装。
- 两台机器准备匹配的**朱／紫 4.0.0**，解锁交换。接收端可以是原厂机。
- 先手动完成一次两机本地交换，确认本地无线正常。USB 是电脑控制派送机的通道，不是两机间的交换线，也不使用路由器 IP LAN。
- 派送机停在大地图，关闭对话和盒子。**备份派送端存档，留空盒子 1 第 1 格**；此格会写入待派送个体。
- 两台游戏保持离线，同时保持本地无线可用。

网页下单后会尝试已保存的 USB 端口；首次若只识别到一台派送机，会自动连接。多台设备或需手动重连时才展开「USB 连接设置」，选择／输入实际 USB 端口并连接。**USB 端口不是 TCP 6000。** 无设备时仍可生成并排队，但不会显示「已完成」。

本网页直接固定 USB + SV 本地模式，关闭自动文件池分发、Discord/Twitch 等集成；本地失败不会退回联网交换。更多硬件细节和指针限制见 [本地交换说明](SV-LOCAL-TRADE.zh-CN.md)。

## 配置与队列

- 中文／英文搜索种类，常用配置预填；高级 PS 文本折叠显示，需要时再改。
- 复用现有 **PKHeX Showdown 解析 → Auto-Legality 生成 → 合法性/可交换性检查 → SysBot SV 队列与交换例程**，不是另写一个生成器或模拟派送。
- 每批 **1–12 只**；全部生成并检查通过才一起入队。任何一只失败，**整批不入队**，明确指出第几只并保留原文本。
- 只接收朱紫传统配置：EV 单项 0–252、合计不超过 510；IV 单项 0–31；等级 1–100。不支持冠军 `SPs:` 行，也不把冠军 32/32/2 静默乘以 8；若写成 `EVs: 32 ...`，它就按真实的 32 EV 处理。
- 首版限制**朱紫原生来源**，不生成需要跨作转入的个体，不放宽 HOME tracker 检查；不允许自定义训练家覆盖或批处理指令。目录中可选不代表任意形态、球种、招式、异色组合都有原生合法来源。
- 生成后核对指定物种、形态、有效性格/IV（含薄荷与极限训练）、特性、招式、EV、等级、球和语言等；不靠悄悄改掉请求来宣称成功。
- 「待派送」可立即取消；已经准备、搜索或交换的单不能从网页取消。取消不承诺撤销恢复，原输入仍在，可以重新下单。
- 状态明确区分 **待派送／准备中／正在搜收货人／交换中／已完成／派送失败／已取消**；只有上游交换完成通知才能标记「已完成」。排队不等于已收货。
- 同次服务运行中，原样重试复用请求 ID，不重复入队。改动配置会成为新请求。
- 浏览器保存输入；程序保存 USB 端口。**队列和请求去重仅在本次运行内保留，关闭程序会清空。** 刷新网页不清队列；关闭网页不停止后台程序。
- ALM 自身超时不保证取消底层计算，因此遇到生成超时会停止接受后续生成并提示重启服务，不叠加未知后台任务。重启前检查已收货内容，避免重复派送。

## 故障时

- 无 USB：检查数据线、usb-botbase 和驱动，再刷新识别。缺少原生库时重新解压**完整**运行包，不单独复制 exe。
- 配置失败：按「第 N 只」与原因修改后重新下单；失败不会偷偷把前面的几只入队。
- 设备退出／断线：正在处理的单标为失败，其余待派送单保留；连接恢复后继续。**失败可能存在结果不确定性，先看接收端是否已经收到，再决定重新派送。**
- 网页显示连接中断：检查程序窗口是否仍开着。网页会保留输入、标记上次队列为旧状态，并暂停提交／取消；恢复后自动读取。
- 地址被占用：关闭重复启动的本工具，或用环境变量 `SYSBOT_WEB_PORT` 换一个本机端口。
- 本网页仅监听 `127.0.0.1`，不面向公网；不是给手机远程访问的服务。

- 真实 Chrome + 本地 HTTP 后端：默认异色巨金怪实际生成入队；皮卡丘＋伊布实际整队生成并按序排队；取消、错误保留、同请求重试、跨站写入拦截、刷新保留输入均通过。320px／390px 无横向溢出、无浏览器脚本异常。

## 开发与复现

需要 .NET 10 SDK；浏览器测试另外需要 Node.js。

```powershell
dotnet build SysBot.NET.slnx -c Release
dotnet test SysBot.NET.slnx -c Release --no-build

npm ci
npx playwright install chromium
npm run test:web

# 可改用已安装的 Chrome，省去下载浏览器：
$env:TEST_BROWSER_CHANNEL = 'chrome'
npm run test:web

# 发布自带运行时的 ZIP：
./scripts/publish-web.ps1
```

`TEST_DOTNET` 可指定 SDK 的 dotnet.exe 路径。`TEST_WEB_DLL` 可选择独立发布目录中的 DLL；`TEST_WEB_EXE` 可直接运行自带运行时的 exe，以验收完整运行包。测试会自启 5218 端口的服务并在结束后关闭，产出 `artifacts/web-browser-check/` 中的报告、截图与日志，不连接 Switch。

`SYSBOT_WEB_DATA` 可指定 USB 设置文件目录；`SysBot.Web.exe --no-browser` 只启动服务而不自动打开网页。

源码：<https://github.com/Moeblack/SysBot.NET/tree/feature/sv-local-trade>；项目保持 AGPL-3.0。libusb 为独立动态链接的 LGPL-2.1-or-later 组件，可替换；来源、源码与哈希见 `libusb-README.md`，许可见 `COPYING.libusb`。
