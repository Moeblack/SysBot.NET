本地派送台：流程与设计取舍

范围：朱／紫本地 USB 派送，默认一只、Showdown 整队入队、逐只接收。无 Discord、无远程资源、无确认弹窗。

product-design / shape userflow

任务简报

用户在本机快速派一只，或一次粘贴整队。目标是少量操作完成排队，不反复连接和确认。对象为派送单；提交把配置按顺序交给本地服务，实际交换不可撤销。仅 queued 单可以取消，取消不承诺撤销恢复；需要恢复时重新派送。后端校验配置，前端不模拟成功、不转换冠军 SP。非目标：账户、云端、战队管理和参数大全。

流程一 · 派一只

1. 进入派送台

显示真实设备状态、固定交换码与默认巨金怪。目录和状态分别加载；设备未接 USB 仍允许服务校验生成并入队，连接中断则暂停提交。

主动作 → 选择种类或使用默认值；目录错误 → 保留输入并提示重新打开页面。
2. 选择与检查

中文／英文目录搜索，单独勾选闪光。选种类载入默认配置，闪光仅改 Shiny 行。高级配置按需展开，不打断主路径。

主动作 → 派送这一只；空输入或目录未选中 → inline 提示。
3. 排队与接收

服务成功返回才显示入队数量；保留配置。USB 未连接时显示设备未连接，队列仍为待派送，不冒充交换中。按 03180318 搜索，收完一只同密码再搜。

分支 → queued 可取消；preparing / searching / trading 不显示取消。

流程二 · 贴队伍

1. 切换贴队伍

粘贴传统 Showdown 队伍，每只以空行分隔；可用皮卡丘＋伊布示例开始。两种输入独立保存。

2. 一起派送

主按钮始终叫“一起派送”，旁边显示估计识别数，最终数量由后端校验。单次提交禁用编辑与按钮，失败保留 requestId；同次程序运行内原样重试避免重复入队，编辑配置才换新 id。

3. 逐只交换

同一队列逐只准备、搜索、交换；可取消还没开始的单。失败原因在对应单上显示，取消竞争以服务实际状态为准。

已运行 node --check；隔离浏览器 API 场景验证中文搜索载入模板、勾选闪光保留其他行、两只示例、失败后原 requestId 重试、仅 queued 显示取消、服务断开禁用提交并显示连接中断。320px 视口无横向溢出，浏览器无脚本异常。测试数据只注入验证浏览器，不包含在生产资源中。

开放项与暂缓项

无未决的主流程设计。身份权限、历史清理、队伍模板库和撤销已交换宝可梦不在本次范围。当前前端队伍计数是空行分组估计，不替代后端 Showdown 解析；USB 自动连接及实机交换仍待设备验收。
